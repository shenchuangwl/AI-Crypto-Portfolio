## 先用一句话抓住全貌

把 525 个 USDT 永续想成招聘：

- **观察区**：简历过了初筛，放进待看名单。
- **符合区**：面试过了，进入「候选人名单」。可以盯、可以对比，**还不能发 offer**。
- **确认区**：背调 + 终面都过了，才进 DMR（执行层）。名额刻意很少。

系统每 **15 分钟**扫一轮。一只币、一个方向（涨或跌）各走自己的梯子，每轮最多升 **一级**。不会出现「这一轮从观察直接跳到确认」。

页头「符合 12 / 确认 0」是 **上涨池 + 下跌池加总**。只点「上涨候选池」时，表里可能只看见 3 只；另外 9 只在下跌池。两边对不上，不是漏数。

下面按你标出的 5 段，逐段拆开。

## 1. 「待够时间 + 连过若干轮」到底在防什么

### 1.1 为什么不能「这一轮分数高就升级」

加密货币 15 分钟里冲一下、下一轮就没了，非常常见。如果只看当轮分数，确认区会变成「谁刚好在扫描那一秒冲得高」。

所以升级要过 **两道时间门**，而且必须 **同时** 过：

| 门 | 白话 | 符合 ← 观察 | 确认 ← 符合 |
|---|---|---|---|
| **待够（dwell）** | 在 **当前这一档** 已经待了多久 | ≥ **30 分钟** | ≥ **45 分钟** |
| **连过（streak）** | 连续几轮扫描都通过「上一档的升级检查」 | ≥ **3 轮** | ≥ **4 轮** |

少一门都不升。

### 1.2 「待够」不是持仓时间，也不是 K 线周期

选币榜「停留时间」就是 dwell：

> 进入 **现在这个状态**（观察 / 符合 / 确认）的时刻 → 本轮扫描时刻。

- 不是这根 15m K 线走了多久。
- 不是你开着页面多久。
- 不是开仓持有多久。

扫描约 15 分钟一次，所以停留常按 15m / 30m / 45m 往上跳。不到约 8 分钟界面写成「刚进」。

**例子**：REUSDT 跌向刚 `ENTER_QUALIFIED`，停留 **15 分钟**。就算分数已经很高，确认区要求「在符合里至少待 45 分钟」，它这轮 **时间门就没过**。

**反例**：HOME 跌向已符合 **46 小时**，时间门早过了。它升不上去，是因为分数/阶梯不够（见第 4 节），不是没待够。

### 1.3 「连过」不是「待了几轮」

这是最容易混的一点。

状态机里有一个计数器 `consecutive_pass`（连胜）：

- 在 **符合区** 时：只有当轮通过了 **升确认的全套检查**（第 3 节的 `pass_confirmed`），连胜才 +1。
- 当轮没过这套检查：连胜 **清零**（不是减 1）。
- 升入符合的那一轮，连胜会被 **清成 0**，从零开始为「升确认」重新数。

所以：

> 在符合区待了 20 轮 ≠ 连过了 20 轮。

现盘 12 只符合的连胜 **全是 0**。意思是：它们待了很久，但 **没有任何一轮** 同时过了「Score 76 + SS 70 + M 72 + C 0.75」。连胜根本没开始加。

升确认至少还要 **连续 4 轮** 都过这套检查。一轮 15 分钟，连 4 轮大约再 **1 小时**，且中间不能断。断一轮，从 0 再数。

### 1.4 两道门合在一起的最短路径

生产路径每轮最多升一级，且 **不开启** `SM_FAST`（实验室才会一轮连跳）。

粗算最快：

```
观察：待满 30m，且连续 3 轮够「升符合」
   ↓  （大约 30–45 分钟）
符合：待满 45m，且连续 4 轮够「升确认」
   ↓  （大约再 1 小时）
确认
```

理论最快大约 **两小时量级**，还要求中间每一轮分数/结构都不能掉。现盘这批符合卡在「检查从未连续通过」，不是卡在「时钟没走完」。

### 1.5 掉下去也要「连着差」

升级严，降级也不是一轮就踢：

- 符合区：Score 掉到 **56 以下**，还要 **连续 2 轮**，才打回观察。
- 所以 TUT 现分 56.5、贴着退出线，仍挂在符合——它是「还没被踢」，不是「刚刚够格新进」。
- ZBT 现分 55.3，已经低于 56，状态机记了 **fail=1**。再一轮低分，就会打回观察。

## 2. 当轮 `pass_qualified`：怎样才算「够格进符合」

必须 **已经在观察区**。然后当轮这 4 条 **全部** 成立（再叠加第 1 节的 30 分钟 + 连 3 轮）：

| 检查 | 门槛 | 白话 |
|---|---|---|
| Score | ≥ **62** | 总分过线，像「综合面试分」 |
| 阶梯 SS | ≥ **55** | 走势有台阶，不是一根针 |
| 动量 M | ≥ **60** | 1h/4h/24h 方向上的力度够 |
| 流通量 | 必须有 | CoinGecko 对得上标的；对不上不能升符合/确认 |

缺一条，这轮就不算「够格升符合」，观察区的连胜也会断。

### 2.1 Score（总分）是什么

不是交易所的涨跌幅，是本系统把几项 0–100 分加权加总（`scan.py` `composite_score`）：

| 零件 | 权重 | 来源 |
|---|---|---|
| 阶梯 SS | 30% | Gate4 |
| 动量 M | 25% | Gate2（1h/4h/24h + RSI） |
| 流动性 S_L | 15% | Gate1（成交额是否够大、稳） |
| 市值动量 S_MC | 10% | Gate3 |
| 一致性 C | 10% | Gate2（三个周期是否同向；内部用 C×100） |
| 排名 / 风险 | 各 5% | 现网排名项常按中性 50，风险项常按 100 |

另外有数据质量帽：`min(加权和, 40 + 0.6×DQ)`。现盘符合币 DQ 多是 95，帽子约 97，一般不是瓶颈。

**62 分**大约是：流动性过线之后，动量和阶梯「还过得去」。525 个合约里，每天能筛出大约十来只到符合，所以符合区「看起来够」。

### 2.2 阶梯 SS 是什么

Gate4 看 1 小时 K 线像不像「楼梯」：一阶一阶往上（或往下）走，而不是一根大阳就结束。

它会看：有几级台阶、每一级待多久、回撤是否规矩、量能不能跟上、趋势方不方正。权重按设计 §28 合成 0–100。

- **SS ≥ 55**：至少有一点台阶感，够格当候选人。
- **SS ≥ 70**（确认才要）：台阶清楚、回撤可控，才配进执行层。

现盘很多符合币 SS 只有 **42–45**：涨（或跌）是真的，但结构是「一波冲」，不是「走出来的楼梯」。所以能进符合，进不了确认。

### 2.3 动量 M 是什么

Gate2 用最近 **1 小时 / 4 小时 / 24 小时** 涨跌，加上 1 小时 RSI：

- 上涨方向：三个周期涨得越「扎实」（大约 5% 算很强），M 越高；RSI 更喜欢在 60 附近，不喜欢超买到 80+。
- 下跌方向：三个周期跌得越扎实，空头 M 越高。

**M ≥ 60** 是「这个方向上有力」。确认要 **72**，等于要求趋势更干净、更强。

### 2.4 「有流通量」为什么一票否决

符合 / 确认会用到流通市值、市值动量。流通量来自 CoinGecko（对不上或为 0 就算缺供应）。

缺供应时：

- **不能新进** 符合、不能新进确认；
- 若已经在确认，会被 **打回符合**。

现盘 12 只符合的未确认原因是 `dwell_or_streak`，**不是** `supply_missing`。它们卡的是分数/阶梯/连胜，不是映射。

### 2.5 进符合之后，留在符合比「新进」容易

进门要 62。进了以后，只要 Score 还在 **56** 以上，就继续留着。  
这就是「进门严、出门松一点」，避免在 62 上下来回抖、榜单闪进闪出。

所以榜上会看到：

- 刚进符合、分还在 70 附近的（如当时的 CYS）；
- 已经符合十几个小时、分掉到 56～61、只是还没被踢的（如 TUT、ZBT）。

两者都叫「符合」，含金量不一样。看符合区时，建议同时看 **Score 和停留**：分高 + 停留不长 = 新候选人；分贴 56 + 停留很长 = 老候选人在衰减。

## 3. 升确认：在符合里再过一轮「更窄的门」

必须 **已经在符合**。同一轮要同时：

1. 在符合里待满 **≥ 45 分钟**；
2. **连续 ≥ 4 轮** 通过下面整张「确认检查表」；
3. 当轮 `pass_confirmed` **每一项都过**（没有「差 0.7 分通融」）。

### 3.1 两张门槛对照（核心表）

| 项 | 进符合 | 升确认 | 直观差别 |
|---|---|---|---|
| Score | ≥ 62 | ≥ **76** | 总分再高一档，大约多 14 分 |
| 阶梯 SS | ≥ 55 | ≥ **70** | 楼梯要清楚，不能只是一波冲 |
| 动量 M | ≥ 60 | ≥ **72** | 趋势力度更强 |
| 一致性 C | **进符合不查** | ≥ **0.75** | 1h / 4h / 24h 至少约 3 个里有 2.25→实际是 3 个里至少 3 个同向才稳（见下） |
| 数据质量 DQ | 只进总分帽子 | ≥ **60** | 现盘 12 只都是 95，不是瓶颈 |
| 流通量 | 要有 | 要有 | 一样，缺了两边都不能升 |

C 在实现里是 0、0.33、0.67、1.00 四档（三个周期里有几个和该方向同号）。  
**0.75** 实际上要求 **三个周期全部同向**（C = 1.00）。C = 0.67（两同向一反向）过不了确认。

### 3.2 为什么确认要多看「一致性 C」

符合区可以「4 小时很强、24 小时还在消化昨天」。  
确认区要对执行层负责：如果 1 小时涨、4 小时跌、24 小时又涨，这种票短期好骗眼睛，不适合当「可以动手」的确认。

C = 1.00：三个窗口都站在同一边（全涨或全跌）。  
C = 0.33：三个里只有一个同向，多半是噪音。

### 3.3 「全部要过」= 一票否决

没有加权凑合。CYS 现分 **75.3**，离 76 只差 0.7，动量 85、一致性 1.00 都很好，但 **SS 只有 45**（确认要 70）。SS 不过，整项否决，连胜仍是 0。

可以记成安检：身份证、机票、安检袋，少一样不让过闸，不会因为另外两样特别好就放行。

### 3.4 确认之后怎么掉

确认不是「进了就锁死」：

- Score &lt; **70**，或 SS 掉到确认线的约 **9 成** 以下（70×0.9 = 63），开始记失败；
- **连续 2 轮** 失败，打回符合。

也就是说：确认区要维持「仍然强」，不是「曾经强过」。

## 4. 现盘 12 个符合为什么一个都升不上去

读表口诀：

- **停留很长 + 连胜仍是 0** = 时钟够了，检查从未连续通过。
- **SS 四十多** = 有行情、没楼梯，确认区最常见的拦路虎。
- **C = 0.33 / 0.67** = 三个周期步调不一致，确认区直接否。

- **硬门槛（忽略停留）12 只里 0 只过关。**

## 5. 和「选币榜看见 12 个」怎么对上：整条漏斗

把 525 想成漏斗，每一层扔掉一批，留下更少、更严的。

```
525  有效宇宙
     USDT-M 永续 + 交易中 + 标的是币（不是美股/商品合约）
        │
        │  Gate1 流动性：6/12/26 日成交额够不够大
        ▼
~一半 过流动性（其余直接很难进观察/符合）
        │
        │  观察 WATCH：Score ≥ 45，再连过约 2 轮
        ▼
~318  观察区     「值得盯，还不是候选人」
        │
        │  符合 QUALIFIED：
        │    Score≥62 + SS≥55 + M≥60 + 有流通
        │    + 在观察里待满 30m + 连过 3 轮
        ▼
  12   符合区     「候选人名单，不能进 DMR」
        │
        │  确认 CONFIRMED：
        │    Score≥76 + SS≥70 + M≥72 + C≥0.75 + DQ≥60 + 有流通
        │    + 在符合里待满 45m + 连过 4 轮
        ▼
   0   确认区     「可以交给执行层」
```

层与层的数量差，来自门槛差，不是显示 bug：

| 你看到的数字 | 它实际统计的范围 |
|---|---|
| 页头 / 漏斗「符合 12」 | 涨池符合 + 跌池符合 |
| 页头 / 漏斗「确认 0」 | 涨池确认 + 跌池确认 |
| 上涨表里 3 行 | 只显示涨池、且受搜索/等级/滚动限制 |
| DMR 横幅「暂无确认区」 | 确认 = 0，所以 inbox 为空 |
| 「生产路径无 SM_FAST，需多轮 15m」 | 不会一轮从观察跳到确认 |

符合区「相对够」：62 + SS55 + M60，在 525 里每天都能筛出十来只。  
确认区「经常空」：76 + SS70 + 三周期同向，是给 DMR 的窄口。现盘这批符合多数是中等分数、楼梯不完整，**设计上就不该进确认**。

## 对照着看榜时可以怎么用

1. **先看状态，再看停留，再看分。**  
   「符合 + 刚进 + 70 分」和「符合 + 13 小时 + 56 分」不是同一种票。

2. **想判断会不会升确认，不要只看停留。**  
   停留只说明「待够了没」。还要看 Score 是否靠近 76、SS 是否靠近 70、C 是否是 1.00。现盘连胜全是 0，说明检查从未连续通过。

3. **SS 四十多、M 却八十多**（STAR、CYS）：短线很猛，结构是冲刺。符合区可以挂着看，确认区会挡。

4. **分掉到 56 附近**（TUT、ZBT）：下一轮更该关心会不会 **打回观察**，而不是会不会升确认。

5. **涨/跌池要分开点开。**  
   页头 12 = 两边合计。只看上涨，会漏掉下跌池里更接近确认的（如 CYS）。

## 和界面字段的对应

| 界面 | 机制里的名字 | 记住一句 |
|---|---|---|
| 状态：符合 / 确认 / 观察 | QUALIFIED / CONFIRMED / WATCH | 身份，不是涨跌 |
| 停留时间 | dwell | 当前身份已待多久 |
| 入选时间 | `state_enter_time_utc` | 进入当前身份的时刻 |
| 停留价格 | `state_enter_price` | 进入当前身份时的价，之后冻结 |
| Score↑ / Score↓ | 该方向总分 | 加权综合分，不是 24h 涨跌 |
| SS | 阶梯 | 走得像不像楼梯 |
| M | 动量 | 1h/4h/24h 方向上的力度 |
| C / DirConf 附近的一致性 | `consistency_*` | 几个周期同向（0/⅓/⅔/1） |
| 未确认：`dwell_or_streak` | 时间门或连胜或确认检查没齐 | **不是**缺流通 |
| 未确认：`supply_missing` | 流通量对不上 | 两边都不能升 |
| DMR 横幅 | 只有 CONFIRMED 才写入 | 符合区再多也不会进执行层 |

## 一句话收束

**符合区** = 过了「62 分 + 有点楼梯 + 有点力道 + 观察里待满半小时再连过 3 轮」的候选人名单，允许分稍后掉到 56 仍留着。  
**确认区** = 候选人里再熬 45 分钟，并且 **连续 4 轮** 都达到「76 分 + 楼梯 70 + 力道 72 + 三个周期同向」。  

现盘 12 只都停在第一层——多数楼梯不够、总分不够、连胜从未开始——所以确认是 0。这是窄口过滤器在干活，不是选币榜少画了确认区。
